## The problem

People searching for terms like "IVF package deals" or "IVF refund programs" are close to a decision. They are comparing costs and looking for a provider. A page built around one of those exact searches can meet that intent directly, where a general services page cannot.

The pages had to live inside an existing Webflow site with its own class system, and they had to pass through a staging site before going to production. Anything that clashed with existing styles would break layouts on pages I never touched.

## What I built

I built a set of bottom-of-funnel landing pages, each targeting one high-intent keyword. Examples include IVF package deals, reciprocal IVF, and IVF refund programs.

Each page started life as a self-contained HTML file. That let me write, review, and check every page outside Webflow before importing anything. Once a page was approved, I imported it into the client's Webflow site.

## How it works

The import step is where most of the risk sits, so I treated it as a mapping problem.

1. **Reuse what exists.** Wherever the incoming markup matched an element the site already had (headings, buttons, containers, rich text), I mapped it onto the site's existing classes. The new pages inherit the site's typography and spacing, and a future design change to those classes updates the new pages too.
2. **Prefix what is new.** Sections the site had no equivalent for got new classes with a `ve_` prefix. No new class can share a name with an existing one, so nothing collides when pages move between the staging site and production.
3. **Check before promoting.** Pages went to staging first, then to production once the layout and content matched the approved HTML.

A simplified example of the naming rule:

```css
/* Existing site classes are reused as-is */
.heading-style-h2 { }
.button { }

/* New sections only use the ve_ prefix */
.ve_price-compare { }
.ve_price-compare_row { }
.ve_refund-steps { }
```

The prefix also makes the work easy to audit later. Anyone on the client's team can search the Webflow style panel for `ve_` and see every class this project added.

## Result

The pages are live on the client's production Webflow site, each one built around a single purchase-intent keyword and styled with the site's own design system.
